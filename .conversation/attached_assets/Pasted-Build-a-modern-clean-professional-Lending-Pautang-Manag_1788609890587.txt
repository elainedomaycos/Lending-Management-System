Build a modern, clean, professional **Lending / Pautang Management System** as a **frontend-only web application prototype**.

The system is intended for a small local lending business that currently manages borrowers, loans, collections, and partner/investor records manually using paper listahan. The goal is to replace the paper-based workflow with a simple digital system that is easy to understand and operate.

## IMPORTANT DEVELOPMENT SCOPE

For this version, build **FRONTEND ONLY**.

Do NOT build:

* Backend
* Database
* API
* Authentication backend
* Supabase
* Firebase
* Server-side logic
* Real payment processing
* Real user accounts
* Production data persistence

Use **realistic mock data** throughout the application.

The prototype should nevertheless feel like a real, complete application. Buttons, navigation, filters, tabs, modals, forms, dropdowns, search, and other interactions should work on the frontend using mock/local state where appropriate.

The backend, database, authentication, and production business logic will be implemented later.

---

# PRODUCT DIRECTION

The application should feel like:

**Simple + Professional + Clean + Practical + Easy to Learn**

It should NOT look like:

* A complicated banking application
* A corporate ERP
* An accounting software overloaded with features
* A mobile-only application
* An oversized accessibility interface by default

The primary device is a **10–11 inch tablet in landscape orientation**, with desktop support and responsive phone support.

Use a normal modern SaaS interface.

## Default sizing

Use standard UI sizing:

* Body text: 14–16px
* Table text: 13–15px
* Page titles: 24–28px
* Section titles: 18–20px
* Buttons: 14–16px
* Inputs: 14–16px
* Important financial figures: 24–32px
* Normal card padding
* Normal spacing
* Standard icon sizes

Do NOT make everything excessively large.

However, include an **optional Display Size setting**:

* Standard
* Large
* Extra Large

Default = Standard.

The user can increase the interface size from Settings if needed.

# DESIGN SYSTEM

Create a polished SaaS dashboard design.

Use:

* White/light neutral backgrounds
* Subtle borders
* Rounded cards, but not excessively rounded
* Clear hierarchy
* Professional typography
* Consistent spacing
* Minimal shadows
* Simple line icons
* Clear tables
* Clean forms
* Consistent buttons

Use a professional blue as the primary accent color.

Avoid excessive gradients, glassmorphism, neon colors, excessive animations, or overly decorative elements.

The interface should prioritize information clarity.

## Status colors

Use color together with text labels:

* Green = Paid / Completed / Active
* Yellow = Partial / Attention
* Orange = Extended / Past target period
* Red = Missed / Overdue

Never rely on color alone to communicate status.

# IMPORTANT BUSINESS LOGIC FOR THE PROTOTYPE

The frontend should demonstrate these concepts.

Example loan:

Principal = ₱10,000

Interest Rate = 20%

Interest = ₱2,000

Total Due = ₱12,000

If target collection period = 40 days:

Daily target = ₱12,000 ÷ 40 = ₱300

Timeline:

Day 1–40:
Active / Target Collection

Day 41–59:
Extended / Delayed

Day 60:
Maturity

Day 61+:
Overdue

Balance:

Total Due − Total Valid Payments

Payment status:

Paid:
Payment >= Expected

Partial:
Payment > 0 and Payment < Expected

Missed:
Payment = 0 and payment is overdue

Do not implement complex financial accounting yet. Keep the logic simple and transparent.
